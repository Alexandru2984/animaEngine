# animaEngine 1.0.0-rc3 — audit hardening

Third release candidate. An external review of the rc2 tree (commit
88e0d5f, ~29.8k lines) went looking for the things a self-audit tends to
miss — live dependency advisories, panic paths in the config loader, and
the write side of code whose read side was already guarded. It found
five real issues. rc3 is those fixes and nothing else; the memory soak
is still flat and the published artifacts still check out.

## Security

- **Three live advisories patched.** `quick-xml` 0.37 → 0.41
  (RUSTSEC-2026-0194 quadratic attribute parsing, -0195 unbounded
  `NsReader` allocation) and `crossbeam-epoch` → 0.9.20
  (RUSTSEC-2026-0204). The quick-xml bump matters most: it's the direct
  dependency that parses **untrusted Shimeji pack XML**, so the only
  path an attacker's file could reach is now on a fixed release. Two
  transitive copies remain — a build-time proc-macro and accesskit's own
  D-Bus introspection XML, neither fed untrusted input — with documented
  ignores kept in lockstep between `cargo audit` and `cargo deny`.
- **Shimeji symlink guard fixed.** The pack size/count walk followed
  symlinks because it stat'd through `metadata()`; its `is_symlink()`
  check could never fire. A link inside a pack could send the walk out
  of the pack tree. It's now detected and skipped. (The sprite *copy*
  path was already contained by canonicalisation, so no file was
  copied out — this was the stat walk.)
- **Thumbnail write path contained + decode capped.** An asset id from a
  hand-edited `library.toml` could contain `../` and push a written
  thumbnail outside the cache directory; ids are now restricted to a
  safe filename component. And the thumbnail decoder now enforces the
  same `MAX_IMAGE_DIM` limit as the scene loader, so a small file
  declaring enormous dimensions can't exhaust memory in the thumbnail
  thread.

## Fixed

- **Config loader can't panic on a bad `version`.** `version =
  4294967296` used to wrap to 0 and hit an `unreachable!`; it now clamps
  to the current schema and skips migration, like any other malformed
  version field.
- **Future configs load read-only.** A config from a newer build is no
  longer silently downgraded to the current schema on load.
- **Hot-reload never overwrites your config.** A partially written file
  (an editor mid-save) or a hand-edit typo used to be replaced with
  defaults by the reload worker. Reload is now read-only: on a bad read
  it keeps the running scene and tells you the edit hasn't taken.

## How to help the bake

Same as before: run it on your actual desktop and file an issue if
anything regresses — distro, session type (X11 / Wayland + compositor),
and `RUST_LOG=anima_engine=info` output up to the problem. The import
and hot-reload paths got the most churn this round, so exercising a
Shimeji import and a live config edit is especially useful.
