# animaEngine 0.3.1 — launcher icon patch

Patch release for one bug: 0.3.0 shows up in the GNOME app launcher
with the right *name* but no icon. If you see the icon already,
you're fine; if you see a blank tile next to "animaEngine", this
release fixes it.

## What went wrong

The 0.3.0 `.deb` shipped only the scalable SVG at

```
/usr/share/icons/hicolor/scalable/apps/anima-engine.svg
```

GNOME's Yaru (Ubuntu's default since 20.04) and most other
freedesktop-spec icon themes walk **discrete-size buckets first** —
`hicolor/256x256/apps/`, `hicolor/128x128/apps/`, …, down to
`hicolor/16x16/apps/`. Only when all of those miss does the resolver
fall back to `scalable/`. We had nothing in any of the size buckets,
so the launcher entry rendered with the generic "?" fallback (or
plain empty, depending on theme).

A correctly-installed icon needs a PNG present at *at least one* of
the discrete sizes the resolver checks first.

## Fix

`scripts/render-icons.sh` rasterizes `data/anima-engine.svg` into
seven discrete sizes:

```
build/icons/16/anima-engine.png    1.3 KB
build/icons/24/anima-engine.png    1.5 KB
build/icons/32/anima-engine.png    2.0 KB
build/icons/48/anima-engine.png    2.6 KB
build/icons/64/anima-engine.png    3.0 KB
build/icons/128/anima-engine.png   6.0 KB
build/icons/256/anima-engine.png   8.0 KB
```

Tool priority: `rsvg-convert` (cleanest) → Inkscape → ImageMagick
(`convert`). Distros all ship one of the three; the first one found
wins. Total icon weight added to the `.deb`: ~24 KB.

`Cargo.toml` `[package.metadata.deb].assets` references those seven
PNG paths directly, so `cargo deb` (and therefore `make deb` and
`scripts/build-deb.sh`) ships them automatically. `make install` and
`make uninstall` also handle them, and both refresh
`gtk-update-icon-cache` so the icon shows up without a logout.

`scripts/build-deb.sh` calls `render-icons.sh` before `cargo deb`
runs — building the `.deb` is one-shot, you don't have to remember a
separate step.

## Installing

If you already have 0.3.0 installed:

```bash
sudo apt install ./anima-engine_0.3.1-1_amd64.deb
```

`apt` upgrades in place; `~/.config/animaEngine/config.toml` is
untouched.

If you're new here:

```bash
wget https://github.com/Alexandru2984/animaEngine/releases/download/v0.3.1/anima-engine_0.3.1-1_amd64.deb
sudo apt install ./anima-engine_0.3.1-1_amd64.deb
```

The AppImage path didn't change — `linuxdeploy` already bundles the
SVG, and AppImage installs aren't wired into the system icon theme
anyway. The fix is `.deb`-specific.

## Verifying the icon

After install, you should see PNGs under every size bucket:

```bash
ls /usr/share/icons/hicolor/{16x16,24x24,32x32,48x48,64x64,128x128,256x256}/apps/anima-engine.png
```

And in the cache:

```bash
gtk-update-icon-cache --validate /usr/share/icons/hicolor 2>&1 | tail -3
```

GNOME app launcher refresh: log out / log back in is the cleanest
shot. If you're impatient, `Alt+F2` → `r` (Enter) restarts GNOME
Shell on X11; on Wayland the safe answer is logout.

## Not changed

Every user-facing feature in [0.3.0](v0.3.0.md) carries over
unchanged: multi-monitor, asset library, bounce behavior, easing
curves, sprite groups. This release does *not* touch any code path
that the running binary executes.
