# animaEngine 1.2.1

A patch release. 1.2.0 listed what it had not verified — sound output,
the Flatpak build — and this release is what checking them found.

## What you'll notice

- **The app holds a sound device only while it plays a sound.** Until
  now it opened your audio output at startup and kept it until you
  quit, playing silence, even if no character ever made a sound — so
  your sound server could never put that output to sleep. The device now
  opens with the first sound and closes 30 seconds after the last.
- **It only uses your default audio output.** When that could not be
  opened, 1.2.0 opened another output directly — on Linux, the raw
  hardware behind PipeWire or PulseAudio, outside their volume and
  routing. Now it stays silent instead, and tries again a minute later.
  An output that breaks while in use, such as an unplugged headset, is
  reported once instead of on every buffer, and the next sound reopens
  the default.
- **Relaunching right after Quit works.** A launch that found the
  previous instance still shutting down handed off to it and exited, so
  nothing was left running. It now waits for the old instance to go and
  starts. The same on Windows.
- **The Flatpak starts on Wayland sessions** — GNOME, KDE and the
  rest. It could not before: its permissions withdrew X11 whenever
  Wayland was present, and the overlay draws through X11 (XWayland). Its
  tray icon now appears too.
- **The AppImage no longer prints `xkbcommon: ERROR … dead_hamza`** at
  every start. It uses your system's libxkbcommon instead of an older
  bundled copy.

## Packaging

- **AppImage:** needs `libxkbcommon-x11` installed. Every desktop with
  Qt, GNOME or KDE already has it; if yours does not, the app says which
  package to install instead of crashing.
- **Flatpak:** asks for less. It keeps its config, cache and asset
  library in its own `~/.var/app/com.animaengine.Anima/`, so the grants
  for `~/.config`, `~/.cache` and `~/.local/share` are gone; what remains
  is read-only access to Pictures and Downloads, for dropped files.
  A file dropped from anywhere else cannot be seen inside the sandbox,
  and the drop does nothing — put it in Pictures, Downloads or the asset
  library first. The opt-in native Wayland backend is not available in
  the Flatpak; it uses the X11 path like the other packages by default.
- **Screenshots** in the AppStream metainfo, and a description that
  matches the app as it is now.

## Compatibility

No change to the config, the D-Bus methods, the CLI or the file
locations. See [stability-policy.md](../stability-policy.md).

## Known gaps in verification

Sound was checked end to end on a real X server, with the audio written
to a file: a script's sound arrives on time and panned to the
character's side. The Flatpak was built and run on the test setup: it
starts, draws, shows its tray and accepts a dropped file. Still not
verified: sound inside the Flatpak, multi-monitor on real hardware, and
anything on Windows. `docs/runtime-findings.md` has the detail (R47–R49).

The full list is in [CHANGELOG.md](../../CHANGELOG.md).
