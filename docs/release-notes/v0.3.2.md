# animaEngine 0.3.2 — launcher icon, for real

0.3.1 shipped the PNGs at every hicolor size. The freedesktop-spec
compliant theme lookup found them. GNOME Shell on Ubuntu's Wayland
session still rendered the launcher entry without an icon. 0.3.2
fixes the two related spec-corner cases that caused it.

## What was missed

### 1. `.desktop` filename ≠ AppStream `<id>`

The `metainfo.xml` declares:

```xml
<id>com.animaengine.Anima</id>
```

But the `.desktop` file was named `anima-engine.desktop`. GNOME Shell
47+ on Ubuntu uses the filename↔id match as a primary key for icon
resolution in the dock and launcher. Even with a perfectly valid
`Icon=anima-engine` field and a correct hicolor theme lookup,
Mutter silently treated the entry as having no resolvable icon.

This isn't documented in the Freedesktop Icon Theme Specification —
it's a convention AppStream enforces in practice across modern
GNOME / Dash to Dock / Ubuntu Dock stacks, and one cargo-deb
doesn't catch.

**Fixed**: renamed to `data/com.animaengine.Anima.desktop`. Makefile,
cargo-deb assets, and `scripts/build-appimage.sh` updated. `make
uninstall` also clears the legacy `anima-engine.desktop` so users
upgrading from 0.3.0/0.3.1 don't end up with two launcher entries.

### 2. WM_CLASS / app_id mismatch

The `.desktop` declared:

```
StartupWMClass=animaEngine
```

But winit by default derives both X11 WM_CLASS and Wayland `app_id`
from the binary name — i.e. `anima_engine` (snake_case). At runtime,
the dock matched windows to launcher entries by that identifier and
saw a mismatch, so the running app showed up as a *second* entry
with a placeholder icon alongside the pinned one.

**Fixed** in `src/app.rs`:

```rust
let attrs = WindowAttributesExtX11::with_name(attrs, "animaEngine", "animaEngine");
let attrs = WindowAttributesExtWayland::with_name(attrs, "animaEngine", "animaEngine");
```

Both APIs accept the same identifier. The runtime window's identity
now matches `StartupWMClass=animaEngine` exactly, so the dock binds
the running window to the pinned entry.

## Installing

```bash
sudo apt install ./anima-engine_0.3.2-1_amd64.deb
```

dpkg sees the filename change between the two versions of the
`.desktop` file and cleans the old entry automatically. No manual
removal needed.

## After install

The PNGs are on disk from 0.3.1 already; this release doesn't ship
new icon files. What changes is the lookup chain GNOME walks.

For the launcher icon to appear, **Mutter's in-session app-icon
cache has to be rebuilt from scratch**. That cache is
session-lifetime and nothing a post-install hook can touch — not
`gtk-update-icon-cache`, not `update-desktop-database`, not even
unpin/repin via `gsettings`.

Cheapest path: **logout + login**. Guaranteed path: **reboot**. On
the next session start, GNOME Shell sees the renamed `.desktop`
file, resolves the icon through the unchanged hicolor PNGs, and the
launcher entry appears with the Ghost Mascot.

## Not changed

Every user-facing feature in 0.3.0 carries over. This release
touches packaging metadata + two extension-trait calls on
`WindowAttributes`. The compiled binary is byte-different from
0.3.1 but only at those call sites.

## Sorry for the back-and-forth

If you're upgrading from 0.3.0 → 0.3.1 → 0.3.2 in 24 hours, sorry
for the churn. The launcher-icon problem turned out to have two
hidden contributing causes and I fixed them one at a time instead
of stepping back and looking at the whole AppStream / Mutter
binding chain. 0.3.2 should be the last patch in this series
unless something else surfaces.
