# animaEngine 0.6.0 — platform completeness

The two oldest platform gaps close in this release: global shortcuts
on GNOME/KDE Wayland sessions (via the GlobalShortcuts desktop
portal), and the multi-monitor data model that shipped in 0.3 finally
getting its render-side implementation.

## Global shortcuts everywhere

Until now, `Ctrl+Shift+A/H/P` worked through XGrabKey — fine on X11
and XWayland, impossible on native Wayland. 0.6.0 adds the sanctioned
Wayland mechanism:

- On sessions exposing `org.freedesktop.portal.GlobalShortcuts`
  (GNOME ≥ 48, KDE Plasma ≥ 5.27, wlroots with a capable portal
  backend), animaEngine binds its three global actions through the
  portal. The desktop shows a one-time approval dialog; bindings are
  remembered per app-id. This works on native Wayland, needs no
  XWayland, and survives the Flatpak sandbox.
- The handshake runs on a background thread — a permission dialog
  left on screen for minutes cannot block startup.
- Declining the dialog falls back to XGrabKey where an X server
  exists, with a toast explaining the downgrade; the warning banner
  only appears when no mechanism is available at all.
- Pin a backend explicitly with `hotkey_backend = "auto" | "portal"
  | "x11" | "none"` under `[global]` in config.toml. The Keybindings
  tab shows which backend is live.

## Real multi-monitor rendering (closes C.3)

`MonitorMode::PerMonitor` — the default since 0.3 — used to be
positioning math only; entities resolved to a secondary monitor were
distributed by the data layer but never rendered. Now:

- One overlay window per monitor, each with its own click-through
  input shape; entity coordinates live in global desktop space and
  translate per window.
- The GPU state is shared: one device, one pipeline, one entity
  texture cache — an entity moving between monitors never re-uploads
  its frames.
- Dragging works across monitors; edit mode flips every window's
  input region in lockstep; the settings panel stays on the primary.
- Unplugging a monitor mid-session relocates its pinned entities
  (with a toast) and rebuilds the window set; plugging one in adds
  its window on the next heartbeat.
- Single-monitor machines: one window, behaviourally identical to
  0.5.x. `Span` mode keeps the exact pre-0.6 single-window path.

## Suspend, resume, stalls

`docs/soak-testing.md` documents the resilience protocol, including
a fact worth knowing: Linux suspend freezes `CLOCK_MONOTONIC`, so
resume creates **no** animation backlog by construction. The case
that does stress the timing machinery — SIGSTOP/debugger stalls — is
covered by a scripted test (run and passing on this release).

## Known limitations (read before relying on 0.6 features)

This release ships without field validation on two paths, because no
compatible test environment was available at release time. Both have
automatic fallbacks to previously tested behavior:

1. **The portal arm is untested live.** The development environment
   (Ubuntu 24.04, portal backend GNOME 46) does not expose
   GlobalShortcuts — that backend arrived in GNOME 48. The portal
   client is built to spec with the protocol logic unit-tested, but
   no real portal has answered it yet. If it misbehaves on your
   GNOME 48 / Plasma session: set `hotkey_backend = "x11"` (or
   `"none"`) in config.toml and please open an issue with the log.
   Sessions without the portal are bit-identical to 0.5.5.
2. **Multi-monitor is validated logically, not physically.** The
   window-planning math is unit-tested and the single-monitor
   degenerate case is smoke-tested live; actual dual-monitor
   behavior (window placement, hotplug events, cross-monitor drag)
   has not run on real hardware. `monitor_mode = "span"` restores
   the pre-0.6 behavior wholesale if anything misbehaves.
3. Per-output layer surfaces on the **native Wayland** path are
   explicitly out of scope for 0.6 (single surface as before);
   PerMonitor there is 0.7+ material.

## Audit notes

Focused review areas for this release (full history in
`docs/threat-model.md`): the portal session handshake stores no
tokens or secrets in config (the portal persists bindings by app-id
on its side); portal events flow through a bounded channel with the
same drop-on-overflow semantics as the D-Bus service; extra windows
get their own XShape regions with the same passthrough guarantees;
the window registry is rebuilt wholesale on mode/topology changes
(no stale-window reuse). 279 lib tests at the release boundary,
clippy `--all-targets -D warnings` clean, `cargo audit` + `cargo
deny` green.

# Debian / Ubuntu
sudo apt install ./anima-engine_0.6.0-1_amd64.deb
