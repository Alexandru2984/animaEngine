# animaEngine 0.8.0 — polish, provenance, and windows to land on

The polish release promised since 0.2. Every surface got deliberate
attention, driven by a heuristic UX audit
(`docs/ux-audit-0.8.md`) whose fix list became the scope — so this
isn't ad-hoc fidgeting, it's a worklist worked to completion. Riding
the same cycle: release-engineering infrastructure, crash visibility,
a benchmark suite, and one genuinely new feature.

## Polish (Faza V)

- **Reduced motion.** One Appearance-tab toggle (`reduced_motion` in
  config) disables every UI transition — panel slide, tab cross-fade,
  toast fade, palette pop — and the decorative entity bobbing, while
  animations that *convey state* keep playing. egui's built-in
  animation clock is zeroed with it. The same pass added the motion
  that was missing: the settings panel now slides instead of
  snapping, toasts rise as they fade in, the palette pops on open.
- **First-run tour.** Three coach-mark bubbles on the overlay itself.
  The first is button-free and advances when you enter edit mode — the
  exact action it teaches — because in pass-through mode only the ⚙
  button is clickable. Skippable, re-armable from "Reset onboarding
  hints", and shown only to genuinely fresh installs (upgraders are
  exempt by design).
- **Inspector ergonomics.** Sliders carry units (px, px/s, s, fps, ×);
  opacity reads as a percentage and parses "85%" back; double-click
  resets scale, opacity and fps to their defaults.
- **Keyboard-first command palette.** Ctrl+K, then ↑↓ + Enter over a
  flat result list. The old palette grabbed focus every frame, which
  made Tab navigation impossible and left the second button of each
  preset row unreachable — both fixed. The ⚙ button shows a
  theme-aware focus ring.
- **High-contrast correctness.** The toggle button, keybinding accents
  and toast success color were inline RGB literals invisible to theme
  switching. They now read the active palette, so the high-contrast
  variants restyle them like everything else; the toggle glyph
  contrast moved from ~2.1:1 to compliant.
- **Every hardcoded string is gone.** ~20 toasts, the entire context
  menu, the ⚙ tooltips and the last inspector labels flow through
  fluent now. A recurring discovery: many keys had been translated in
  the 0.4 locale audit and never wired into the code.

## Full locale catch-up

Every one of the eight non-en/ro locales (de, es, fr, it, ja, nl, pl,
pt-BR) received its untranslated backlog — ~110 strings each, reaching
back to 0.4 (the keybindings tab, action labels, the what's-new
panel). Every locale now ships a fully translated UI; the only keys
left equal to English are genuine cognates ("Position", "Animation").
A human native review remains welcome before 1.0; the
`docs/locale-audit/` statuses track it.

## Window-awareness (X11)

`window_awareness = true` (or the Scene-tab toggle) makes
physics-enabled characters land on and walk along the top edges of
your open windows — falling off at the edges, riding a slowly-moved
window. The classic Shimeji trick, the highest-demand behavior we'd
been skipping at import. EWMH-based: `_NET_CLIENT_LIST` + frame
extents on a ~300 ms poll, NORMAL windows only, minimized excluded,
our own dock-type overlays never qualify. Off by default. **On Wayland
the toggle is inert** — the protocol exposes no global window
geometry; the probe runs once and the feature stays silent.

## Infrastructure

- **Tag-triggered release automation.** Pushing a `vX.Y.Z` tag builds
  the .deb + AppImage in CI, checksums them, attests build provenance
  (Sigstore via GitHub OIDC — verify with `gh attestation verify`),
  and opens a *draft* release. Publishing stays a human click. Both
  packaging scripts embed a dependency SBOM in the binary
  (`cargo auditable`).
- **Crash reports.** A panic now writes a local report (version,
  message, location, backtrace) under `~/.cache/animaEngine/crashes/`
  and the next launch points a toast at it. A desktop-launched crash
  used to vanish without a terminal to print to. Reports never leave
  the machine.
- **Criterion benchmarks** over the per-frame hot paths, plus a weekly
  CI canary that archives the history. `scene_tick/100` ≈ 8.5 µs
  against the 8 ms engine budget.
- **CI hardening**, two rounds: rustdoc/MSRV/machete/metadata gates,
  cargo-nextest with flake-naming, dbus-session smoke on the release
  artifact, workflow hygiene (read-only token, concurrency, actionlint)
  and weekly beta/Wayland/coverage canaries.

## Audit notes

Regression-focused, as planned, with one new surface: the X11 window
watcher. It is **read-only** — `get_property` / `get_geometry` /
`translate_coordinates` against the X server the app is already
connected to, no writes, no new file or network access, and it only
reads geometry from the user's own session. Off by default. The video
loader gained a real decoder round-trip test that immediately caught a
since-0.1 bug (SPS/PPS primer wiped before the decoder saw it). 347
lib tests, clippy `--all-targets -D warnings` clean, `cargo audit` +
`cargo deny` green, rustdoc clean.

## Known limitations

- **Visual matrix and Orca walkthrough are recommended before relying
  on the a11y claims.** The polish work is code-complete and the
  parity tests pass, but the {Dark, Light, Dark-HC, Light-HC} × {en,
  ro} × {mouse, keyboard} render matrix and the GNOME Orca screen-
  reader pass need a human at a real session. They are tracked in
  `docs/ux-audit-0.8.md` §"Manual pass".
- Window-awareness and portal shortcuts remain field-unvalidated on
  the hardware/compositor combinations the dev box can't provide (see
  the 0.6.0 notes); both fall back automatically.
