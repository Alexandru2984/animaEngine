# animaEngine 0.5.2 — medium-severity follow-up + doc cleanup

Closes the four medium-severity findings that 0.5.1's hot patch
listed as "accepted / deferred" and applies a documentation
language sweep. Smaller surface than 0.5.1, all low-urgency —
take the update at your leisure regardless of which backend you
run.

## Fixed — medium-severity audit follow-ups

### M2 — library asset paths could escape `library_root`

A hand-edited `library.toml` carrying an absolute path or a `../`
segment used to lift the resolved asset target out of the library
root via `Path::join`. The decoder downstream would then attempt
to read whatever file the malformed entry pointed at; even if the
decode failed, the error reply was a probe-friendly signal of
which files exist.

Fix: new `resolve_library_asset(root, relative)` helper
canonicalises both sides with `Path::canonicalize` and rejects
anything where the resolved target doesn't `starts_with` the
canonical root. Wired in `app.rs::handle_library_outcome` before
`pre_validate_dropped_file`. Three new unit tests cover the
accept / absolute-escape / `../`-escape cases.

### M3 — `$HOME` fallback could be redirected via env injection

`directories::ProjectDirs::from()` returns `None` on systems
without XDG dirs (unusual on Linux but possible in containers).
The previous fallback was `$HOME/.cache/animaEngine` with `HOME`
defaulting to `.`, so a wrapper invocation
`HOME=/etc/cron.d anima-engine` could redirect writes anywhere
the user had access to.

Fix: the fallback is now
`std::env::temp_dir().join("animaEngine-<uid>")` in
`perf::cache_dir`, `asset_library::xdg_data_dir`, and
`asset_library::xdg_cache_dir`. `temp_dir` honours `TMPDIR` but
always resolves to an absolute path, and the uid suffix isolates
users on shared hosts. `libc` was already in the dep tree
transitively; promoted to a direct dependency for the `getuid()`
call.

### M4 — info-level traces leaked full paths into journald

Drop / library spawn / library reject log lines used
`tracing::info!("…: {}", path.display())`, which broadcast the
user's home directory, any private folder name in between, and
the file name into journald / syslog. Other users with read
access to the journal could enumerate that.

Fix: new `drop_validate::redact_path` helper returns just the
file name component. Info-level lines log that; the full
absolute path is downgraded to `debug!` (off by default, opt-in
via `RUST_LOG=anima_engine=debug`). Affected sites: drag-drop in
both X11 and Wayland paths, library-outcome rejection.

### M5 — `util::tmp_sibling` predictable name across instances

`atomic_write_bytes` wrote to `<path>.anima.tmp` and renamed.
Two animaEngine instances racing past a missed single-instance
lock (no D-Bus, or lock acquisition failed) would both write to
the same temp name; the later writer truncated the earlier one
mid-write.

Fix: `tmp_sibling` now embeds `std::process::id()` →
`<path>.<pid>.anima.tmp`. The rename target stays unchanged so
atomicity guarantees are preserved.

## Changed — documentation language

- "Faza X" replaced with "Phase X" across all English-language
  docs (CHANGELOG, release notes, threat model, architecture,
  AppStream metainfo). The Romanian word had leaked from internal
  notes into shipped artifacts.
- Lingering "Claude" mentions in the D.4 locale audits replaced
  with neutral "automated AI cross-check" / "the LLM" framing.
  The methodology is unchanged — confidence labels per locale
  still apply, native review is still required — just the naming
  is neutralised.

## Tests

257 pass (231 lib + 25 integration + 1 demo). Three new unit
tests in `drop_validate`. `cargo clippy --all-targets -- -D warnings`
clean.

## Upgrade notes

`config.toml` files saved by any prior version decode unchanged.
No behavioural change for users who haven't hand-edited
`library.toml` and don't run the binary with an unusual `HOME`
value.

```bash
# Debian / Ubuntu
sudo apt install ./anima-engine_0.5.2-1_amd64.deb

# AppImage
chmod +x animaEngine-0.5.2-x86_64.AppImage
./animaEngine-0.5.2-x86_64.AppImage
```

## Audit status post-0.5.2

All findings from the 0.5.0 audit are now addressed (3 critical
+ 4 high in 0.5.1, 4 medium in 0.5.2). The remaining
informational-only items (L2-L5, I1-I3) stay accepted with no
action — they're either confirmed not-bugs, paranoid asserts
already in place, or documented invariants.
