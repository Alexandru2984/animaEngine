# animaEngine 0.5.1 — Wayland security patch

Hot on the heels of 0.5.0, an audit of the new native Wayland
backend turned up eight findings — three critical, four high, one
informational. This release closes all of them. The default X11
backend is unaffected; only users running
`ANIMA_USE_WAYLAND_NATIVE=1` are exposed to the underlying
issues.

## Who needs this update

- **X11 (default)**: at your leisure. None of the fixes touch the
  X11 path.
- **`ANIMA_USE_WAYLAND_NATIVE=1`**: **upgrade promptly**. Three of
  the fixes close DoS / unbounded-allocation paths reachable by
  other local processes on the same session bus.

## What was vulnerable

### Critical — bypassed the drop pre-validate gate

The X11 path runs every dropped file through a cheap stat-based
gate (200 MB size cap, extension whitelist, regular-file check)
**before** the decoder sees it. The 0.5.0 Wayland drop path
skipped this gate entirely. A `.png` of arbitrary size or a
file with an unsupported extension could reach the decoder.

### Critical — unbounded drop worker thread

The 0.5.0 Wayland drop path spawned a fresh `std::thread::spawn`
per drop and called `pipe.read_to_end(&mut buf)` with no cap. A
malicious source could:

- send gigabytes through the pipe → main loop OOM;
- never close the fd → worker thread blocked forever, fd leak per
  attempt;
- spam drag events → unbounded thread spawn until `RLIMIT_NPROC`.

### Critical — unbounded D-Bus action queue

The 0.5.0 Wayland D-Bus service (`org.animaengine.Anima` with the
five methods added in E.6 — `Activate`, `ToggleEditMode`,
`HideOverlay`, `ShowOverlay`, `ToggleGlobalPlayback`) wrote events
into an unbounded `mpsc::channel`. A spammy session-bus peer
(`gdbus call` in a tight loop) grew memory without bound between
two frames of the main loop.

### High — URI-list parser unbounded

The `text/uri-list` parser did `text.lines().filter_map(...).collect()`
with no cap. A payload of arbitrary-many `file://` lines produced
an arbitrary-large `Vec<PathBuf>`.

### High — `percent_decode` broke UTF-8

`(h * 16 + l) as char` folded each escaped byte into a Latin-1
codepoint instead of part of a multi-byte UTF-8 sequence. Files
with diacritics in their names (`anima%C8%9Bie.png` →
`animație.png`) silently failed to drop.

### High — fuzz harness only checked panic-freedom

The 0.5.0 fuzz target for the URI-list parser would have caught
panics but not the unbounded `Vec<PathBuf>` allocation it was
exposed to.

### High — threat model out of sync

`docs/threat-model.md` still declared a "single-method invariant"
on `com.animaengine.Anima`. The Wayland backend in 0.5.0 added
four methods.

### Informational — control characters from xkb to egui

`KeyEvent::utf8` from sctk's keyboard handler passed control
characters (e.g. `\x01` for Ctrl+A) straight to
`egui::Event::Text`. An egui `TextEdit` would store them.

## What's fixed

| # | Fix |
|---|---|
| 1 | `src/drop_validate.rs` is the new shared validator; both X11 and Wayland drop paths + the library "Add to scene" outcome call it before reaching the decoder. |
| 2 | Drop worker reads via `pipe.take(64 KiB)`, the worker count is bounded at 4 via an `AtomicUsize` + `Drop` guard, and the result channel is `sync_channel(16)` with `try_send`. |
| 3 | D-Bus queue switched to `sync_channel(64)` with `try_send`; the consumer loop coalesces idempotent toggles (XOR parity per frame) so 1000 `ToggleEditMode` calls between two frames apply 0 or 1 toggle, not 1000. |
| 4 | URI-list parser uses `.take(MAX_URI_LIST_PATHS)` (256). New unit test asserts the cap; fuzz target asserts the same. |
| 5 | `percent_decode_to_string` accumulates raw bytes and reinterprets as UTF-8 (`String::from_utf8`); malformed sequences are rejected rather than substituted. New tests cover multi-byte filenames and rejection. |
| 6 | Fuzz targets assert output bounds and round-trip equivalence in addition to panic-freedom. |
| 7 | `docs/threat-model.md` documents the expanded D-Bus surface honestly: same-user processes can spam any method, per-frame coalescing + bounded queue together bound the blast radius, future methods need a threat-model review entry. |
| 8 | `KeyEvent::utf8` from xkbcommon is filtered through `c.is_control()` before `egui::Event::Text`. |

## Upgrade notes

`config.toml` files saved by 0.5.0 (or earlier) decode unchanged.
The Wayland backend remains opt-in via `ANIMA_USE_WAYLAND_NATIVE=1`;
defaults haven't moved. Behaviour you would notice as a user:

- Files with diacritics drag-drop correctly now on Wayland
  (`animație.png` etc.).
- Drag-drop with > 256 files at once: only the first 256 spawn;
  the rest are silently dropped with a log warning. The previous
  unbounded behaviour wasn't expected by anyone in practice.

## Test suite

254 tests pass (228 lib + 25 integration + 1 demo). Clippy clean
on `--all-targets`.

## Process notes

This release was driven by a follow-up audit run against the
0.5.0 codebase. The audit caught regressions that the implementing
work didn't (Wayland drop bypassed an X11 invariant; D-Bus surface
expansion went into the wire without updating the threat model
text). Going forward the plan is to bake "did you update
docs/threat-model.md?" into any PR that touches D-Bus method
surface or asset-input validation.

## What's next

No new features in 0.5.1 — security only. Locale audits from
0.4's D.4 infrastructure continue arriving as native-speaker PRs;
those will land in 0.5.x patches as they come. Phase F (macOS /
FreeBSD) stays gated on hardware access.
