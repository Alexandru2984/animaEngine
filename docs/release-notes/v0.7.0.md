# animaEngine 0.7.0 — content & feature completion

The release's spine is the multi-state animation engine. On top of
it: Shimeji pack import — instant access to an existing ecosystem of
thousands of community-made desktop mascots — plus the last two
"lands later" promises from 0.3 finally landing. Nothing visible in
the UI is stubbed anymore.

## Multi-state animations

Entities now carry up to four animation sequences and switch between
them automatically:

| State | Plays when |
|-------|-----------|
| `drag` | the user is dragging the entity |
| `fall` | gravity is on and the entity isn't grounded |
| `walk` | a behavior moves it horizontally |
| `idle` | otherwise |

- Declared as additive `[characters.animations.<state>]` TOML tables
  (asset path/type + optional per-state fps). **Legacy configs are
  untouched**: a single-sequence character loads exactly as before
  and its config never gains the new key on save. A typo'd state
  name fails the parse loudly instead of vanishing.
- Missing states fall back to `idle`; a state asset that fails to
  load warns and falls back instead of killing the entity.
- Facing follows horizontal motion and persists when the entity
  stops; the renderer mirrors sprites by flipping texture
  coordinates — no duplicated textures, no extra pipeline state.

## Shimeji pack import

Drop a Shimeji pack folder (`conf/` + `img/`) onto the overlay — or
paste its path in the Library tab — and the mascot walks out of the
box:

- `actions.xml` parses through a hardened pipeline: quick-xml (which
  implements no DTD/entity expansion at all — the classic XML-bomb
  class is dead by construction), 2 MiB/file + depth-32 +
  4 KiB-attribute caps, and every `Image` reference canonicalised
  under the pack root — `../` escapes are skipped with a reason.
- Stay/Move/Fall/Dragged actions map onto the four states; walk
  speed derives from pose velocities (px/tick × 25), per-state fps
  from pose durations (ticks × 40 ms, clamped).
- Sprites are **copied** into `<library>/imported/<pack-slug>/` in
  pose order — deleting the downloaded pack later can't orphan your
  scene. The library scanner deliberately skips `imported/` so
  hundreds of sequence frames don't flood the asset grid.
- Anything unmappable (Java `Embedded` actions, wall-climbing,
  multi-mascot interactions) is skipped with a written reason —
  toast shows the count, the log has the details. Spec + caps:
  `docs/shimeji-import.md`.

## Library thumbnails (closes C.5)

The asset rows show real previews: generated on a background thread
at startup (first frame, 64 px box, regenerated when the source
file's mtime moves), picked up from disk by the UI as they appear,
cached GPU-side with a hard cap. Videos keep the film glyph — a
64 px preview isn't worth an H.264 decode.

## Group composition (closes C.9)

A group's `offset_x/y` and `scale` now do what they always promised:
members render transformed (all three render paths), clicks hit-test
against the transformed quad (including per-pixel alpha at effective
scale), and the inspector shows the effective transform with the
owning group's name.

## Audit notes

New attack surface this release is the importer, built hardened from
the spec onward: no DTD expansion, stat-based pack caps before any
decode, path containment with a traversal test that plants a real
escape target, programmatic fixtures only (no binaries in the repo).
The state cache reuses the per-path asset cache unchanged (each
state is a separate asset). The aggregate memory budget counts every
state. 300 lib tests, clippy `--all-targets -D warnings` clean,
`cargo audit` + `cargo deny` green.

Known limitation carried from 0.6.0: portal shortcuts and
multi-monitor remain field-unvalidated (see the 0.6.0 notes); both
fall back automatically.

```bash
# Debian / Ubuntu
sudo apt install ./anima-engine_0.7.0-1_amd64.deb

# AppImage
chmod +x animaEngine-0.7.0-x86_64.AppImage
./animaEngine-0.7.0-x86_64.AppImage
```
