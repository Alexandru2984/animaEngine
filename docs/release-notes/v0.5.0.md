# animaEngine 0.5.0 — native Wayland reaches parity

Phase E. The 0.3.x line landed the engine; 0.4 polished the UX
surface. 0.5 closes the **Linux** half of "platform reach" by
making the native Wayland backend a real choice rather than a
proof-of-concept. macOS and FreeBSD ports stay explicitly out of
scope — they need hardware to verify on, and shipping target
declarations without verification is worse than not shipping them.

## Highlights

### Full native Wayland backend (`ANIMA_USE_WAYLAND_NATIVE=1`)

The opt-in `wlr-layer-shell-unstable-v1` path used to render
sprites and nothing else; the UI surface lived on the X11 path
only. 0.5 closes that gap — every UX feature the X11 path exposes
is now available on wlroots compositors (sway / Hyprland / river /
Wayfire) without going through XWayland.

Quick start:

```bash
ANIMA_USE_WAYLAND_NATIVE=1 anima-engine
```

If the compositor doesn't advertise `zwlr_layer_shell_v1` (GNOME
Mutter, KWin), the binary silently falls back to the X11 path
with a warning — same as before.

### What's wired on the native path

| Feature | Status |
|---|---|
| Animated sprites | ✓ |
| Click-through (toggle ⚙) | ✓ via `wl_surface::set_input_region` |
| **Keyboard input** | ✓ — sctk xkbcommon, full keysym + modifier decoding |
| **Pointer input + modifiers** | ✓ — cached modifier mask attached |
| **Drag-drop files** | ✓ — `wl_data_device` + `text/uri-list` |
| **Egui paint (settings panel, palette, toasts, context menu)** | ✓ |
| **Multi-monitor enumeration** | ✓ — `wl_output` logical position / size / scale |
| **HiDPI scaling** | ✓ — egui `pixels_per_point` follows compositor scale |
| Perf overlay (`Ctrl+Shift+\``) | ✓ |
| Global shortcuts | D-Bus methods + compositor bindings (see below) |
| Tray icon (StatusNotifierItem) | ✓ |

### Global shortcuts on Wayland — the D-Bus path

`XGrabKey` doesn't exist on a native Wayland session. animaEngine's
substitute: a small **`org.animaengine.Anima`** D-Bus interface
exposing `ToggleEditMode`, `HideOverlay`, `ShowOverlay`,
`ToggleGlobalPlayback`, `Activate`. Bind them from your
compositor's config to mimic the X11 global hotkey UX.

**sway** (`~/.config/sway/config`):

```
bindsym Mod4+Shift+a exec gdbus call --session \
    --dest com.animaengine.Anima \
    --object-path /com/animaengine/Anima \
    --method com.animaengine.Anima.ToggleEditMode
```

**Hyprland** (`~/.config/hypr/hyprland.conf`):

```
bind = SUPER SHIFT, A, exec, gdbus call --session --dest com.animaengine.Anima --object-path /com/animaengine/Anima --method com.animaengine.Anima.ToggleEditMode
```

Full bindings for sway / Hyprland / river in
[docs/wayland.md](../wayland.md).

### Fuzzing harness

A small `cargo-fuzz` setup under [`fuzz/`](../../fuzz/) covers the
three parsers closest to untrusted input:

- `keychord_parse` — `KeyChord::FromStr`, the entry point for
  `[keybindings.map]` table values in `config.toml`.
- `uri_list_parse` — the drag-drop URI-list parser added in 0.5.
- `asset_type_detect` — the dropped/library file path classifier.

Invariant for every target: **never panic** on adversarial input;
return a typed error or a sensible default. Runs on a nightly
toolchain via `cargo +nightly fuzz run <target>`. See
[docs/fuzzing.md](../fuzzing.md) for the CI snippet.

## What's explicitly *not* in 0.5

- **No macOS port.** Without a Mac to verify on, wgpu Metal might
  compile but real-world latency, AT-SPI replacement, packaging,
  and event-loop differences haven't been exercised. PRs welcome.
- **No FreeBSD port.** Same honest stance — the Linux code largely
  ports, but the XCB shape extension call and packaging differ in
  ways that need a real FreeBSD box.
- **No XDG GlobalShortcuts portal.** The D-Bus + compositor
  bindings approach gives users a working substitute today without
  pulling a Wayland portal dependency.
- **No native AccessKit AT-SPI publication on Wayland.** The
  runtime toggle keeps working (egui tree-update generation can be
  disabled), but the AT-SPI bridge is wired by egui-winit which
  the native Wayland path doesn't use. Screen-reader users on
  wlroots should stay on the X11 backend until upstream egui ships
  a Wayland adapter.

These don't block the 0.5 release; they're called out so users on
those platforms know what to expect when they download the .deb /
AppImage.

## Upgrade notes

`config.toml` files saved by 0.4 decode unchanged. The native
Wayland backend stays opt-in. The default X11 path is unmodified —
existing users see nothing different unless they set
`ANIMA_USE_WAYLAND_NATIVE=1`.

```bash
# Debian / Ubuntu
sudo apt install ./anima-engine_0.5.0-1_amd64.deb

# AppImage
chmod +x animaEngine-0.5.0-x86_64.AppImage
./animaEngine-0.5.0-x86_64.AppImage
```

## What's next

The "Linux first" promise is delivered. Future direction depends
on contributors with the relevant hardware:

- **macOS port** — wgpu Metal compiles; the work is window
  attribution, AT-SPI replacement (NSAccessibility), `.app`
  packaging, event loop differences.
- **FreeBSD port** — most Linux code carries over; the missing
  piece is the X11 shape extension call (use libxext-dev),
  packaging via `make pkg`, and a CI box.
- **XDG GlobalShortcuts portal** — adds support for the
  GNOME/KDE-native shortcut model on top of the existing D-Bus
  surface.
- **AT-SPI on native Wayland** — needs an upstream egui-winit
  equivalent for the Wayland surface backend, or a hand-rolled
  adapter.

Patches over the 0.5 series cover incoming locale audits (the D.4
infrastructure ships translations as English placeholder for
several locales pending native-speaker review).
