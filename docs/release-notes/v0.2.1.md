# animaEngine 0.2.1 — startup-crash patch

Patch release for a single nasty bug: 0.2.0 crashed on startup on
distros that don't ship `libxkbcommon-x11` preinstalled. If your
0.2.0 install works, you don't need this update. If it died with

```
Library libxkbcommon-x11.so could not be loaded.
```

— this is the fix.

## What went wrong

In 0.2.0 we turned on the AccessKit feature for `egui-winit` so
screen readers on Linux could see the UI. AccessKit on Linux uses
`accesskit_unix`, which `dlopen`s `libxkbcommon-x11.so.0` at runtime
rather than linking it through ELF NEEDED tags.

Three downstream consequences slipped through:

- `linuxdeploy` couldn't see the dependency when packing the AppImage
  (it walks NEEDED tags, not `dlopen` calls)
- `cargo-deb`'s `$auto` reads the same NEEDED tags, so the `.deb`
  didn't declare a dependency either
- The CI smoke test runs on a minimal Ubuntu image that doesn't
  pull `libxkbcommon-x11` through any other package, so it crashed
  the same way

Three independent fixes, one root cause.

## Fixes in this release

| Surface | Fix |
|---------|-----|
| **AppImage** | `scripts/build-appimage.sh` now resolves `libxkbcommon-x11.so.0` via `ldconfig` on the build host and passes it through `--library` to linuxdeploy. The library is bundled inside the AppImage. |
| **`.deb`** | `[package.metadata.deb]` `depends` now explicitly lists `libxkbcommon-x11-0`, so `apt install` pulls it in on fresh systems. |
| **CI** | All four jobs that compile Rust (`clippy`, `test`, `build`, `smoke`) now install `libxkbcommon-x11-dev` alongside the existing system deps. |

## Installing

### Debian / Ubuntu (.deb)

```bash
wget https://github.com/Alexandru2984/animaEngine/releases/download/v0.2.1/anima-engine_0.2.1-1_amd64.deb
sudo apt install ./anima-engine_0.2.1-1_amd64.deb
```

### AppImage (any distro)

```bash
wget https://github.com/Alexandru2984/animaEngine/releases/download/v0.2.1/animaEngine-0.2.1-x86_64.AppImage
chmod +x animaEngine-0.2.1-x86_64.AppImage
./animaEngine-0.2.1-x86_64.AppImage
```

### Upgrading from 0.2.0

No config migration needed — `~/.config/animaEngine/config.toml` is
read by both versions unchanged.

If you installed 0.2.0 via `.deb`:

```bash
sudo apt install ./anima-engine_0.2.1-1_amd64.deb
```

If you ran 0.2.0 via AppImage, just replace the binary.

If you built 0.2.0 from source on a machine that already had
`libxkbcommon-x11-0` installed, you don't have to do anything — the
0.2.0 binary worked for you. But pulling the patch keeps your CI
green next time you push.

SHA-256 checksums:

```
5a16a7ec1c695c4765a854b938e618303d6ccef793f787b97173565af4a58de1  anima-engine_0.2.1-1_amd64.deb
041c98b620153c656d2edc64efd6d826d8d27a839718e09ff60dc5c7f053a41f  animaEngine-0.2.1-x86_64.AppImage
```

`.deb` depends on `libxkbcommon-x11-0` explicitly now (verifiable with
`dpkg-deb --field anima-engine_0.2.1-1_amd64.deb Depends`).

AppImage bundles `libxkbcommon-x11.so.0` directly (verifiable by
running `./animaEngine-0.2.1-x86_64.AppImage --appimage-extract
'usr/lib/libxkbcommon*'`).

## Not changed

Everything in [0.2.0](v0.2.0.md) carries over unchanged: themes,
tabbed sidebar, presets, command palette, ten locales, AccessKit
bridge. This release does *not* touch any user-facing feature.
