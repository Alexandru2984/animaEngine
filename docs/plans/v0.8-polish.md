# v0.8 — UI/UX polish (Faza V)

Umbrella: [docs/roadmap-1.0.md](../roadmap-1.0.md). Rolling-wave:
scope here is the *method*; the concrete worklist is produced by V.0
itself and becomes the release's contract. One sub-phase = one
commit, standard gate.

Theme: the dedicated polish phase promised since 0.2 — no new
capabilities, every surface gets deliberate attention. Polish without
an audit is just fidgeting, so the audit comes first and the release
ships its list.

**Scope exception (approved 2026-06-12):** one capability rides in
0.8 — *window-awareness* (X11 EWMH windows as physics platforms),
implemented pre-V.0 alongside the release-automation / crash-report /
benchmark infrastructure work. Rationale: 0.9 freezes features, so
0.8 is the last train before 1.0, and it's the highest-demand Shimeji
behavior we skip at import. V.0's audit matrix must cover its UI
surface (the Scene-tab toggle) like any other.

## V.0 — Heuristic audit (M) — produces the scope

- Method: walk every surface in a fixed matrix — {Dark, Light,
  Dark-HC, Light-HC} × {en, ro} × {mouse, keyboard-only}.
- Output: `docs/ux-audit-0.8.md` — numbered findings, each tagged
  `fix` / `wontfix(reason)`, grouped by surface. Severity:
  blocker / paper-cut / nice.
- The `fix` list **is** V.1–V.6's backlog; anything found later
  goes to 0.9-bugfix or post-1.0, no scope creep.

## V.1 — Motion & transitions (M) — DONE 2026-06-12

- Panel slide/fade, tab cross-fade, toast spring, palette pop —
  all through `crate::anim` curves (no new dependency).
- New a11y toggle: reduced motion — disables transitions *and*
  entity idle bobbing; default follows nothing (no portal setting
  exists for it on all desktops) — plain config knob, Appearance tab.

## V.2 — First-run experience (M) — DONE 2026-06-12

- Empty first launch: offer demo scene + 3-step coach-marks
  (replaces static onboarding hints); dismiss-forever, re-armable
  from Appearance (existing reset-onboarding flow).
- *As shipped:* the demo scene was already auto-seeded on first run
  (no "offer" step needed). Coach-marks float on the overlay: step 1
  is button-free (pass-through mode delivers no clicks) and advances
  on the action it teaches — entering edit mode; steps 2–3 carry
  Next/Skip. The contextual chip hints **stay** — they serve
  per-surface discovery (Phase-D decision), the tour serves first
  contact; both re-arm through the existing reset button.

## V.3 — Inspector ergonomics (M) — DONE 2026-06-12

- Control grouping, units on sliders (px, %, fps), double-click-to-
  reset, drag acceleration, per-section reset buttons.
- *As shipped:* units as proper egui suffixes (px, px/s, s, fps, ×;
  opacity renders as a percentage with a parser that accepts "85%");
  double-click-to-reset on scale (1×), opacity (100%) and fps
  (`config::default_fps`), advertised via hover hint. Grouping was
  already sound (collapsible sections). Dropped: per-section reset
  buttons (double-click covers the per-control case; a section-wide
  destructive reset without undo is a footgun) and drag-acceleration
  tuning (egui's default pointer-distance acceleration is adequate).
  Bonus: every slider label routed through i18n (audit F12).

## V.4 — Keyboard & a11y re-audit (M)

- Focus order on every panel; visible focus on custom widgets;
  AccessKit tree re-validated with Orca on GNOME; contrast re-checked
  after V.1's visual changes (HC variants must keep WCAG AAA).

## V.5 — Visual consistency (S)

## V.6 — i18n for new strings (S)

## V.7 — Release 0.8.0 (S)

## Definition of done

The V.0 list is empty or explicitly wontfixed; keyboard-only and
Orca walkthroughs complete without dead ends; reduced-motion honored
everywhere; HC contrast still AAA.
