# v0.9 — Stability freeze (Faza W)

Umbrella: [docs/roadmap-1.0.md](../roadmap-1.0.md). Rolling-wave:
firm scope; harness details finalised at phase start against
whatever 0.6–0.8 actually shipped. One sub-phase = one commit,
standard gate.

Theme: prove the 1.0 contract before promising it. Feature work
stops the day W.0 lands; everything after is measurement, hardening
and paperwork.

## W.0 — Config schema versioning (M) — DONE 2026-06-13

- `version = 2` top-level field (v1 = implicit, everything pre-0.9).
- Migration registry: ordered chain over `toml::Table` (`migrate_v1_v2`,
  applied on load when file version < current); `config.toml.bak-v<n>`
  written before the first migration runs.
- Forward-compat: unknown keys are *preserved* through load→save
  round-trips (serde `flatten` catch-all), so a 1.1 config opened by
  1.0 doesn't silently strip new fields.
- Tests: round-trip per migration, idempotency (migrating twice =
  once), corrupted-version handling (unparseable → treat as current
  + warn, never destroy).
- *As shipped:* migration runs on a parsed `toml::Table`, then
  `Value::try_into` deserialises (re-serialising a raw table would
  trip TOML's "value after table" rule — `version` is a top-level
  scalar that sorts among the section keys). v1→v2 is an honest
  identity migration: all 0.2–0.8 config growth was additive
  (serde defaults), so there's nothing to rewrite yet; the chain
  exists so the first non-additive change has a tested slot.
  Forward-compat preserves unknown `[section]` tables (not unknown
  root scalars — TOML ordering makes those unrepresentable alongside
  `version`). 9 migration tests.

## W.1 — Soak harness (M) — DONE 2026-06-13

- `scripts/soak.sh`: Xvfb + synthetic scene (16 entities, mixed
  asset types, behaviors on), samples every 60 s via the perf
  export: RSS, `Scene::total_decoded_bytes`, texture count, frame
  p95. Emits `soak-report-<date>.md` with verdicts (flat / drift
  slope).
- CI: nightly 30-minute variant, fails on RSS slope above threshold.
- `docs/soak-testing.md` (started in T.10) gains the 7-day desktop
  protocol: real session, suspend/resume cycles, monitor hotplug,
  locale switch — checklist + where to read the numbers.
- *As shipped:* metrics come from a new env-gated `soak` module
  (`ANIMA_SOAK_METRICS=<path>` → one CSV row per interval; zero-cost
  otherwise), not the chrome-tracing export — a flat CSV is what awk
  regresses dependency-free. The script least-squares-fits RSS slope
  and exits non-zero on DRIFT or < 3 samples. CI variant is 10 min /
  20 s sampling (not 30 min) to stay a good nightly citizen on shared
  runners; the 30-min and 7-day protocols are documented as manual.
  2 emitter tests + validated end to end locally (16 textures, flat
  RSS).

## W.2 — Leak hunt (M) — DONE 2026-06-13

- Fix what W.1 finds. Pre-registered suspects: egui texture deltas,
  toast queue growth, hotplug window-registry remnants, portal
  session re-binds.
- *As shipped:* W.1's soak ran flat, so W.2 was a proactive audit
  (boundedness ledger in docs/soak-testing.md). All four pre-registered
  suspects — plus hot-reload threads, the perf ring and the thumbnail
  cache — are bounded with cited mechanisms; the toast bound and the
  flake are already tested. The **only** real growth was the on-disk
  decoded-frame cache (content-addressed keying orphans a file on every
  asset edit, never reclaimed): `cache::sweep` now evicts oldest-first
  past a 1 GiB cap at startup, off-thread. No unbounded memory growth
  found. 7 new tests.
- **Pre-registered flake — RESOLVED (2026-06-12):** the intermittent
  single-test failure from 0.6/0.7 development was named by the
  nextest retry harness (pulled forward post-0.7.0) on its first
  local occurrence: `perf::tests::p95_returns_top_quantile`. Root
  cause: the test timed 100 real near-zero frames and asserted
  p95 ≥ avg — one descheduled iteration created an outlier that
  dragged the mean above p95. Fixed by injecting synthetic totals
  (deterministic quantile assertions). Nothing left for W.2 here
  unless a *different* name shows up.
- Exit criterion: 24 h soak flat before moving on; the 7-day run
  starts here and rides through W.8.

## W.3 — Perf HUD completion (M) — DONE 2026-06-13

- VRAM estimate (decoded bytes + GPU texture bytes), texture
  uploads/frame, draw calls, GPU pass time via `TIMESTAMP_QUERY`
  where supported (feature-detect, hide row otherwise).
- The HUD becomes the soak's visual twin — same numbers, live.
- *As shipped:* VRAM (decoded + texture-cache bytes), texture count +
  uploads/frame, and draws/frame are live in the HUD — the soak's
  visual twin, fully validatable. Per-frame upload/draw counters are
  `Cell`s on `GpuShared` (render borrows it `&`), captured-and-reset
  at frame start. GPU *pass time* is **feature-detected and logged at
  init** but the timed readback is deferred: it needs an adapter that
  exposes `TIMESTAMP_QUERY`, which CI's llvmpipe does not (the dev
  box's Intel iGPU does — so it's a testable follow-up, not a
  guess). Shipping untested async-readback GPU timing in the freeze
  would defeat the point.

## W.4 — Fuzz expansion (M) — DONE 2026-06-13

- New targets: `cache::deserialize_frames` (own binary format),
  `avcc_to_annex_b` (NALU walk), Shimeji XML importer.
- Seed corpora from real assets + fixtures; nightly short CI run;
  `docs/fuzzing.md` updated. Closes the threat-model TODO list.
- *As shipped:* three new cargo-fuzz targets (`cache_deserialize`,
  `avcc_nalu_walk`, `shimeji_xml`) over the hand-written parsers (the
  upstream `image`/`mp4` decoders have their own suites). Functions
  exposed `#[doc(hidden)] pub` (or a `fuzz_parse_actions` wrapper that
  doesn't leak the private parsed type). Committed seeds under
  `fuzz/seeds/<target>/`; a schedule-only nightly CI job seeds the
  corpus and runs all six targets 60 s each. No nightly/cargo-fuzz on
  the dev box, so validated via `cargo check --manifest-path
  fuzz/Cargo.toml` (type-checks every target on stable).
