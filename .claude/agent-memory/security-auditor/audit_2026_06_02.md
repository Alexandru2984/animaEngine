## Key findings

- Single `unsafe` block at `src/wayland/layer_window.rs:193` for wgpu surface creation from raw Wayland handles. Justified but fragile — relies on drop ordering.
- `openh264-sys2` dependency uses `cc` crate to compile C code at build time — supply chain surface.
- Config file save/load uses no atomic write (write-rename pattern) — TOCTOU risk.
- Asset cache under `~/.cache/animaEngine/textures/` has no permission hardening (default umask).
- `pgrep` process execution in `src/window/linux.rs:38` — safe but static args only.
- D-Bus IPC surface via `org.animaengine.Anima` — no authentication beyond D-Bus session scope.
- No network sockets opened — zero remote attack surface.
- No hardcoded credentials or telemetry.
- Serde deserialization bounded by MAX_ENTITIES (64) and field validation.

## Hotspots for future audits
- `src/wayland/layer_window.rs` — unsafe FFI, drop ordering
- `src/config.rs` — file I/O, path resolution
- `src/animation/cache.rs` — cache file creation, deserialization
- `src/animation/video_loader.rs` — C codec via openh264
- `scripts/build-appimage.sh` — downloads executable from internet
